## What system/approach is used

This repository manages JavaScript/TypeScript dependencies through **npm** declared in `package.json` but resolved and locked by **Bun**, which is configured via `bunfig.toml`. The project uses a single-package workspace (no workspaces) and relies on Bun's lockfile (`bun.lock`) as the source of truth for reproducible installs. A **private Google Cloud Artifact Registry** (`europe-west4-npm.pkg.dev/lovable-core-prod/sandbox-npm-cache/...`) hosts cached copies of packages — including several `@lovable.dev/*` packages — so installs resolve from that internal mirror rather than directly from `registry.npmjs.org`.

There is no vendoring of third-party code into `node_modules`; dependencies are installed at install time and committed via the lockfile. There is no `.npmrc`, `pnpm-lock.yaml`, or `yarn.lock`; only `bun.lock` and `package-lock.json` exist, and all package resolution references point to the Lovable Artifact Registry URLs inside `bun.lock`, confirming Bun as the active resolver.

## Key files and packages

- `package.json` — declares all runtime `dependencies` and `devDependencies` using caret ranges (e.g. `^19.2.0` for React, `^5.101.1` for `@tanstack/react-query`). Scripts expose `dev`, `build`, `build:dev`, `preview`, `lint`, and `format` commands driven by Vite, ESLint, and Prettier.
- `bun.lock` — Bun's text lockfile; records exact resolved versions and full artifact URLs (including the Lovable private registry). It also enumerates peer/optional peer dependency constraints for many packages.
- `bunfig.toml` — central configuration for dependency installation behavior:
  - `install.saveTextLockfile = true` ensures `bun.lock` is always written.
  - `install.minimumReleaseAge = 86400` enforces a **24-hour supply-chain guard** that blocks installing any package version published less than one day ago.
  - `install.minimumReleaseAgeExcludes` lists specific `@lovable.dev/*` packages exempted from the age gate (so Lovable tooling can be updated immediately).
- `package-lock.json` — present alongside `bun.lock`, but not the active resolver; it appears to be a legacy/npm-compatible artifact.

## Architecture and conventions

- **Single manifest, single lockfile**: All dependencies live in the root `package.json`; there are no sub-package manifests or monorepo workspaces.
- **Version ranges over pins**: Dependencies use `^` semver ranges in `package.json`, while `bun.lock` pins the exact resolved versions. This allows minor/patch upgrades within the range while keeping builds deterministic.
- **Private registry caching**: Many packages (especially `@ai-sdk/*` and `@lovable.dev/*`) resolve from `https://europe-west4-npm.pkg.dev/lovable-core-prod/sandbox-npm-cache/...`, indicating an organization-wide npm cache/proxy. No `.npmrc` is needed because Bun reads the registry URL from the lockfile entries.
- **Dev vs runtime split**: UI/framework/runtime libraries (`react`, `@tanstack/*`, `@supabase/supabase-js`, `zod`, `tailwindcss`, etc.) go under `dependencies`; build/tooling (`vite`, `typescript`, `eslint`, `prettier`, `nitro`) go under `devDependencies`.
- **No vendoring**: Third-party code is never copied into the repo; reproducibility comes from `bun.lock`.

## Conventions and constraints

- **New packages must be added via `package.json` only**; the lockfile is regenerated by Bun, not hand-edited.
- **Supply-chain age gate**: Any new or updated package published less than 24 hours ago will be rejected by `bun install` unless it is listed in `minimumReleaseAgeExcludes` in `bunfig.toml`. Adding a new exclusion requires explicit approval (the comment says "confirm with the user before adding any").
- **Peer dependency awareness**: Many packages declare peer/optional peer deps (e.g. `@hookform/resolvers` expects `zod ^3.25.0 || ^4.0.0`; `@lovable.dev/vite-tanstack-config` expects `vite >=5.0.0 <9.0.0`, `@tailwindcss/vite >=4.0.0`, `@tanstack/react-start >=1.100.0`). Version bumps should respect these constraints to avoid peer conflicts.
- **Toolchain alignment**: The devDependency set pins a coherent stack — Vite 8.x + React 19.x + TypeScript 5.8.x + ESLint 9.x + Tailwind CSS 4.x + TanStack Start 1.x — and updates should keep these aligned per their peer dependency requirements.
