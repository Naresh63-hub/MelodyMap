The module is a standard Supabase project root. `config.toml` pins the remote project ID (`wlizqxxnfkicjhkffykx`) so `supabase db push/pull` targets the correct cloud instance. All database state lives under `migrations/`, where each SQL file is an idempotent forward-only migration applied in filename order by the Supabase CLI. The first migration creates two tables — `public.profiles` (linked to `auth.users` via FK with cascade) and `public.user_library` (a per-user JSONB store) — then enables Row Level Security on both and attaches fine-grained policies scoped to `auth.uid()`. A shared `touch_updated_at()` trigger function auto-updates `updated_at` columns, and an `on_auth_user_created` trigger on `auth.users` seeds profile rows from auth metadata. The second migration tightens security by revoking execute privileges on those functions from `PUBLIC`, `anon`, and `authenticated`, leaving only `service_role` access.
